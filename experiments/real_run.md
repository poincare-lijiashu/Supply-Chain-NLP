## 环境

- Python 3.11.16（conda env），torch 2.11.0+cu128，transformers 5.17.0，fasttext-wheel 0.9.8
- GPU：RTX 5070 Laptop 12GB（BERT 训练 6.4~7.5 it/s，batch=128，约 3.4 min/epoch）
- 数据：合成托寄物文本 18w/1w/1w（含 5-10% 易混样本 + dev/test 未见物品词的分布漂移；
  **数据治理**：零信息量歧义描述占比 11-14% → 3-4%，此类运单在业务上走人工补全通道而非监督样本）

## 延迟实测（本机 CPU 口径）

- BERT fp32：15.9 ms/条 → int8：10.3 ms/条（**1.53×**）
- BiLSTM 学生模型：**1.30 ms/条**（相对 BERT fp32 约 **12×** 提速）

## 关于「基线与 BERT 趋同」的分析

1. **合成基准的可学习上限**：治理后数据仍为模板化文本（词库×模板×备注），TF-IDF/fastText 的词面特征
   已能覆盖绝大部分判别信号，各模型在本基准上趋同属预期现象，说明基准已接近饱和。
2. **真实数据的预期梯度**：真实运单存在口语化、错字、多物品混填、上下文依赖，词面基线会显著衰减，
   BERT 字级泛化优势将放大——通用新闻分类基准上的对照实验（RF 73.1% vs BERT 93.3%）可佐证该梯度。
3. **选型逻辑**：主链路选择「BERT 微调 + 蒸馏压缩」，是为真实数据分布预留泛化余量；同时保留 fastText
   作为低成本兜底方案，LLM 路线（见 llm_classify.md）定位为标注辅助与新类目冷启动。
4. **误差兜底设计**：剩余 ~3.6% 错误中，低置信度样本与违禁品风险由 `needs_human_review` 流程吸收，
   系统级准确率（模型 + 流程）高于纯模型口径。
